Effect samples

Four ways to use useEffect

  1. 1 Render
  2. 2 Paint
  3. 3 Effects run

Effects run after the browser has painted the screen, which makes them the right place for timers, storage and network calls. Open “View React code” on any card to compare the dependency array with what the demo does.

01

Set up once — empty dependencies

An empty array tells React the effect has nothing to watch. It runs after the first paint and stays quiet, even when the component re-renders.

View React code 
useEffect(() => {
  setRuns((n) => n + 1);
}, []); // nothing to watch: once, after mount
02

Watch a value — [dependency]

List a value in the array and the effect re-runs only when that value changes. Every other re-render leaves it alone.

View React code 
useEffect(() => {
  setRuns((n) => n + 1);
}, [callsign]); // runs again only when callsign changes
03

Clean up an interval

An interval keeps firing after the component is gone unless the effect returns a cleanup function. React calls that function before the next run and on unmount.

View React code 
useEffect(() => {
  const id = setInterval(() => setNow(new Date()), 1000);
  return () => clearInterval(id); // stop when unmounted
}, []);
04

Save a preference to localStorage

The effect mirrors state into browser storage whenever the setting changes, so the choice survives a reload.

View React code 
useEffect(() => {
  localStorage.setItem("week12_2_density", density);
}, [density]);

Exercises

Practice on a working page

Three exercises from Friday's lecture. Try each demo, then read the effect code underneath it.

E1

Keep the tab title in sync

A value outside React — the browser tab title — follows the unread count. Look at the tab after each click.

View React code 
useEffect(() => {
  document.title = `Alerts — ${unread} unread`;
}, [unread]);
E2

Look up a Pokémon

The request lives inside the effect. Waiting, failure and cleanup are all handled, and a new search aborts the request that is still in flight.

View React code 
useEffect(() => {
  const controller = new AbortController();
  setStatus("loading");
  fetch(`https://pokeapi.co/api/v2/pokemon/${name}`, {
    signal: controller.signal
  })
    .then((res) => {
      if (!res.ok) throw new Error("Not found");
      return res.json();
    })
    .then(setPokemon)
    .catch((err) => {
      if (err.name !== "AbortError") setError(err);
    });
  return () => controller.abort();
}, [name]);
E3

Calculate the area, don't store it

Area, perimeter and the square check all come from the width and height during rendering. No extra state variable and no effect are needed.

View React code 
const w = Number(width);
const h = Number(height);

const area = w * h;
const perimeter = 2 * (w + h);
// recalculated on every render — nothing to keep in sync

Key takeaways

Five rules for useEffect

  1. 01

    Effects handle work outside rendering: timers, storage, subscriptions and requests. They run after the paint.

  2. 02

    The dependency array is the schedule. Change the list, change when the effect runs.

  3. 03

    [] means once after mount; a value in the array means “run again when this changes”.

  4. 04

    If an effect starts something, return a function that stops it — clear the interval, abort the request.

  5. 05

    If a value can be calculated from state, calculate it during render instead of adding state or an effect.
