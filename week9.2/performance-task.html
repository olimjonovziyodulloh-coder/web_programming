Website Performance Optimization Report

Olimjonov Ziyodulloh • Student ID 202537557 • Week 9-2

1. Introduction

I used Google Lighthouse (Performance category) to test my Web Programming course archive. The site was already fast, but the first-paint metric (FCP) was in the orange range, because the Google Fonts stylesheet blocked the first render. I applied four optimizations from the lecture checklist and ran Lighthouse again.

2. Before the Optimizations

Initial Lighthouse performance score for the home page. I kept a copy of the home page from before the optimizations so the test can be repeated.

3. After the Optimizations

Lighthouse performance score for the home page after the four optimizations.

4. What I Changed

I stopped the Google Fonts stylesheet from blocking the first paint and loaded only the four font weights the page really uses. I also minified the inline CSS and merged 36 separate SVG shapes into one, so the page went from 20.4 KB to 13.5 KB.

Optimization 1: Non-blocking font stylesheet

A normal stylesheet link blocks rendering until it downloads. I load the fonts with rel="preload" and switch it to a stylesheet once it arrives, so the text appears immediately in a fallback font. A <noscript> copy keeps it working without JavaScript.

Before 
<link href="...fonts.googleapis.com/css2?...&display=swap" rel="stylesheet">
After 
<link rel="preload" as="style" href="...fonts.googleapis.com/css2?...&display=swap"
      onload="this.onload=null;this.rel='stylesheet'">
<noscript><link rel="stylesheet" href="..."></noscript>

Optimization 2: Fewer font weights

The page asked for five font weights, but one of them (Rajdhani 500) was never used. I removed it, so the browser downloads less font data.

Before 
family=Rajdhani:wght@500;600;700&family=Inter:wght@400;500
After 
family=Rajdhani:wght@600;700&family=Inter:wght@400;500

Optimization 3: Minified CSS and HTML

I removed comments, line breaks and extra spaces from the inline CSS and the HTML. The browser reads it the same way, but the file is smaller.

Before 
.week {
    position: relative;
    background: var(--panel);
}
After 
.week{position:relative;background:var(--panel)}

Optimization 4: Fewer DOM elements

The decorative spiderweb in the header was drawn with 36 separate <line> and <path> elements. I merged them into a single <path>, which looks the same but gives the browser less to build.

6. Conclusion

These changes make the first paint start sooner and send fewer bytes to the visitor. The pages also keep their 100 accessibility score, and I did not change how the site looks.
