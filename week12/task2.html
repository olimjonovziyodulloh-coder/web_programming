React state & useState

01

The problem: a plain variable

A local variable is re-created on every render, so React never shows the change. Clicking logs 1, 2, 3 while the count on screen stays at 0.

View React code 
function CounterBug() {
  const logRef = useRef(null);
  let count = 0; // lives in this render only

  function handleClick() {
    count = count + 1;
    const item = document.createElement('li');
    item.textContent = count;
    logRef.current.appendChild(item); // no setState, no re-render
  }

  return (
    <>
      <p>Count: {count}</p>
      <button onClick={handleClick}>+1</button>
      <ul ref={logRef}></ul>
    </>
  );
}
02

useState and functional updates

useState returns the current value and a setter. Using prev => prev + 1 means every quick click reads the latest count instead of a stale snapshot.

View React code 
const [count, setCount] = useState(0);

<button onClick={() => setCount((prev) => prev - 1)}>−1</button>
<output aria-live="polite">{count}</output>
<button onClick={() => setCount((prev) => prev + 1)}>+1</button>
<button onClick={() => setCount(0)}>Reset</button>
03

Multiple useState calls

Each independent field gets its own state variable and setter, so typing an email never touches the name or the age.

View React code 
const [name, setName] = useState('');
const [email, setEmail] = useState('');
const [age, setAge] = useState('');
const [submitted, setSubmitted] = useState(false);

function handleSubmit(event) {
  event.preventDefault();
  setSubmitted(true);
}

if (submitted) {
  return <p>Thanks, {name}! Email: {email}, age {age}</p>;
}
04

State with objects

One object holds the profile, updated with the spread operator. A new object is the signal React needs to re-render.

View React code 
const [user, setUser] = useState({ name: '', email: '', bio: '' });

function handleChange(field, value) {
  setUser((prev) => ({ ...prev, [field]: value }));
}

<input
  value={user.name}
  onChange={(event) => handleChange('name', event.target.value)}
/>
05

State with arrays

Add with spread, remove with filter, toggle with map — three patterns that each return a new array instead of mutating the old one.

View React code 
const [todos, setTodos] = useState([]);

const addTodo = () => {
  if (!input.trim()) return;
  setTodos((prev) => [
    ...prev,
    { id: Date.now(), text: input.trim(), done: false },
  ]);
  setInput('');
};

const removeTodo = (id) =>
  setTodos((prev) => prev.filter((todo) => todo.id !== id));

const toggleTodo = (id) =>
  setTodos((prev) =>
    prev.map((todo) =>
      todo.id === id ? { ...todo, done: !todo.done } : todo
    )
  );
06

Lifting state up

The search page owns the query. The input asks it to change through a callback, and the result list reads the query back as a prop.

View React code 
function SearchPage() {
  const [query, setQuery] = useState('');

  return (
    <>
      <SearchBar onSearch={setQuery} />
      <ResultList query={query} />
    </>
  );
}

function SearchBar({ onSearch }) {
  const [input, setInput] = useState('');

  return (
    <input
      value={input}
      onChange={(event) => {
        setInput(event.target.value);
        onSearch(event.target.value);
      }}
    />
  );
}

07

Counter with history

The lecture challenge: +1, −1, Reset and Undo, plus the last five values. One state object holds the count and the history, so each update replaces both together.

View React code 
const [state, setState] = useState({ count: 0, history: [0] });

function change(delta) {
  setState((prev) => {
    const count = prev.count + delta;
    return { count, history: [...prev.history, count].slice(-5) };
  });
}

function reset() {
  setState((prev) => ({
    count: 0,
    history: [...prev.history, 0].slice(-5),
  }));
}

function undo() {
  setState((prev) => {
    if (prev.history.length < 2) return prev;
    const history = prev.history.slice(0, -1);
    return { count: history[history.length - 1], history };
  });
}
